<!-- feature-intro -->
Give authors visual, self-explanatory choices without turning your templates into a guessing game. Button Box keeps every stored value stable while the Craft control panel shows what that value actually means.
<!-- feature-intro-end -->

<!-- feature-section -->
## Make the right choice obvious

Present the same approved values as separate buttons, button groups, chips, dropdowns, lists, tiles, cards, swatches or visual samples. Add a useful description, familiar icon, image, colour or surface preview so authors can recognise the choice instead of memorising an internal token.
<!-- feature-section-end -->

<!-- feature-grid -->
- :icon[list-check] **Single or multiple** Use Visual Choice for one value or Visual Multi-Choice for a selected set.
- :icon[palette] **Rich visual metadata** Pair stable values with descriptions, icons, colours, images and compound surfaces.
- :icon[layout-grid] **Purposeful presentations** Match the control to the decision, from compact chips to descriptive cards.
- :icon[code] **Project-driven options** Supply choices through PHP when the available options depend on your application.
- :icon[crosshair] **Semantic position** Give authors a spatial picker and receive named values with alignment metadata for your templates.
- :icon[columns] **Widths authors can recognise** Offer approved width stops as a cumulative bar or individual samples, while your stylesheet controls the public layout.
- :icon[star] **Clear ratings** Store a whole-number rating or a real empty value through a familiar control.
<!-- feature-grid-end -->

<!-- feature-section -->
## Set the choices once, use them where they belong

A shared palette or approved set of card treatments should stay consistent across your fields. Manage named option sets in the control panel, edit them from a field's slide-out, and deploy them through project config. When a field needs to go its own way, convert its options to an independent copy.

For reusable starting points, create your own presets or customise the built-in visual, position, width and rating presets. Applying one copies its settings into a field, so later preset edits leave existing fields as you configured them.
<!-- feature-section-end -->

<!-- feature-section -->
## Keep frontend decisions in the frontend

Button Box improves authoring without shipping opinions into your public site. Twig and GraphQL expose stable values and typed choice and position metadata; your project decides how those values affect components, classes, tokens and responsive behaviour.
<!-- feature-section-end -->

<!-- feature-grid -->
- :icon[table-options] **Craft-native administration** Keep labels and values together in compact rows, expand the details when needed, and compare presentations before saving.
- :icon[filter] **First-class Craft behaviour** Use canonical values in element previews, search, filters, conditions, sorting and inline editing.
- :icon[external-link] **Safe editor actions** Add conditional Action Links to field layouts without storing executable JavaScript.
- :icon[brand-graphql] **Typed GraphQL output** Query canonical choices, surface metadata and positions as objects instead of parsing presentation strings.
- :icon[arrows-exchange] **Deliberate upgrades** Preview legacy field conversions, see blockers and warnings, then review the appearance and API changes before opting in.
- :icon[shield-check] **Keep existing content** Retain your existing Button Box fields and scalar APIs while adopting richer choices where they help.
<!-- feature-grid-end -->
